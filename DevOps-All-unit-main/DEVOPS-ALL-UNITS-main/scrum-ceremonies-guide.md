# Comprehensive Guide: Scrum Ceremonies

Scrum ceremonies (or events) create regularity, inspect and adapt progress, and minimize unnecessary meetings. All Scrum events are **time-boxed** (having a strict maximum duration).

---

## 1. Sprint Planning
* **Purpose:** Set the Sprint Goal, choose backlog items, and plan the technical execution.
* **Time-Box:** Max **8 hours** for a 1-month Sprint (typically 2–4 hours for 2-week Sprints).
* **Key Components:**
  * **The Why:** Product Owner proposes the **Sprint Goal**.
  * **The What:** Developers select Product Backlog items for the Sprint.
  * **The How:** Developers break selected items into actionable technical tasks meeting the *Definition of Done*.
* **Example:**
  * *Goal:* "Enable credit card checkout."
  * *Tasks:* API Integration, Form Validation, UI Design.

---

## 2. Daily Scrum (Stand-Up)
* **Purpose:** Inspect daily progress toward the Sprint Goal, adapt the Sprint Backlog, and surface blockers.
* **Time-Box:** **15 minutes** daily (same time and place).
* **Key Guidelines:**
  * Primarily for Developers (Scrum Master / Product Owner participate if delivering work).
  * Focuses on progress, plan for the next 24 hours, and identifying impediments.
* **Example:**
  * *Status:* Finished validation logic yesterday; starting API integration today.
  * *Blocker:* Missing sandbox API credentials (noted by Scrum Master for removal).

---

## 3. Sprint Review
* **Purpose:** Inspect the Sprint outcome with stakeholders and adapt the Product Backlog.
* **Time-Box:** Max **4 hours** for a 1-month Sprint.
* **Key Activities:**
  * Demonstrate completed, "Done" working increment to key stakeholders.
  * Gather direct feedback and evaluate market/business alignment.
  * Product Owner reviews and adjusts the Product Backlog for future sprints.
* **Example:** Team demonstrates live payment feature; Finance requests tax calculations $\rightarrow$ PO adds tax feature to Product Backlog.

---

## 4. Sprint Retrospective
* **Purpose:** Inspect team performance (people, processes, tools) to drive continuous improvement in quality and efficiency.
* **Time-Box:** Max **3 hours** for a 1-month Sprint.
* **Key Discussion Points:**
  1. What went well?
  2. What problems occurred?
  3. How were problems resolved (or not)?
  4. What action items will the team commit to in the next Sprint?
* **Example:** Code reviews delayed testing $\rightarrow$ *Action Item:* Team commits to conducting code reviews within 4 hours of pull request submission.
